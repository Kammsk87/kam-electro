## Backend (FastAPI + PostgreSQL), сервер 31.76.56.125

Код: `vpn-api/main.py`, репозиторий `vpn-api/`.

Auth: Bearer-токены.
- Обычные пользователи — таблица `tokens`.
- Админ — статичный `ADMIN_TOKEN` из `.env`, сверяется напрямую (без таблицы).

### Эндпоинты (реализованы и проверены вживую)
- `POST /api/register`, `POST /api/login` — регистрация/вход пользователя
- `GET /api/me` — данные текущего пользователя (статус подписки, ключи VLESS/AWG по слотам)
- `POST /api/me/renew-key` — перевыпуск ключа в слоте `{slot}`
- `GET /api/admin/users` — список всех пользователей (для админки)
- `POST /api/admin/activate` — `{email, days, reissue}` — продлить/активировать подписку
- `POST /api/admin/block` — `{email}` — заблокировать пользователя: status='blocked', expires_at=now(), удаляет токены (НОВОЕ в этом сезоне)

### Автоматика
`vpn-api/scripts/sync_expired.py` — чистит просроченные/заблокированные аккаунты:
1. Авто-блокирует тех, у кого истёк expires_at (status trial/active → blocked)
2. Находит ВСЕХ заблокированных (включая заблокированных вручную через /api/admin/block), у кого ещё остались выданные ключи
3. Удаляет их клиентов из конфига Xray (по email), рестартует xray если что-то удалено
4. Удаляет AWG-пиры через `AWG_MANAGE_CMD`
5. Чистит строки в `user_vless`/`user_awg`/`tokens`

Запускается через systemd timer `vpn-sync-expired.timer` (каждые 15 минут, `OnBootSec=2min`, `OnUnitActiveSec=15min`) — раньше работало ТОЛЬКО вручную, это было багом: вручную заблокированные пользователи никогда не теряли реальный доступ к VPN. Исправлено и проверено вживую.

⚠️ Важно для коллеги: до этого сезона `sync_expired.py` не имел отдельной ветки очистки для status='blocked' без истёкшего expires_at — если у коллеги есть свои скрипты/cron, которые тоже трогают эту логику, нужно свериться, чтобы не было гонки/дублирования при очистке.

## Frontend (Next.js 16.2.9), сервер 31.76.59.65

Код: `uskoritel-project/`, репозиторий тот же.

### Архитектура проксирования API
`next.config.ts` использует `rewrites()`, проксирующий `/api/*` → `${API_ORIGIN}/api/*` (env-переменная, сейчас `http://31.76.56.125`). Это значит:
- Next.js ОБЯЗАН работать как живой серверный процесс (`next start`), НЕ статический экспорт — rewrites несовместимы со `output: 'export'`.
- Фронтенд НЕ хранит отдельную копию бизнес-логики — всё проксируется на бэкенд 31.76.56.125.

### Страницы (все реализованы, подключены к реальному API, без mock-данных)
- `/` — лендинг
- `/register`, `/login` — регистрация/вход пользователя
- `/cabinet` — личный кабинет: статус подписки, ключи VLESS/AWG по слотам, кнопка "продлить", logout. Загружает данные через `GET /api/me` с Bearer-токеном из `localStorage.token`; при 401/403 редиректит на /login.
- `/admin/login` — вход админа: вводится admin-токен, проверяется вызовом `GET /api/admin/users`, при успехе сохраняется в `localStorage.adminToken`
- `/admin` — админ-панель (НОВОЕ в этом сезоне): список всех пользователей, поиск по email/telegram, статы (всего/trial/active/blocked), кнопки "+30 дней" (activate) и "Заблокировать" (block) на каждой строке

### Деплой на DE-сервере (выполнено в этом сезоне)
- Node.js 20 LTS, nginx, ufw, fail2ban установлены
- UFW: разрешены 22/80/443/tcp, включён
- fail2ban: jail.local (bantime 24h, findtime 10m, maxretry 4, backend systemd) — включён
- Исходники собраны прямо НА сервере (`npm install && npm run build`), не скопирована Mac-сборка (риск нативных бинарников типа SWC под другую платформу)
- `/opt/uskoritel-frontend/.env.production`: `API_ORIGIN=http://31.76.56.125`, `PORT=3000`
- systemd-сервис `uskoritel-frontend.service` — `npm run start` (next start), `Restart=always`, автозапуск включён
- nginx reverse proxy: порт 80 → 127.0.0.1:3000 (`/etc/nginx/sites-available/uskoritel-frontend`)
- Проверено: http://31.76.59.65/ и все страницы отдают 200, проброс /api/* на бэкенд работает
